# Data

All data in this repository is **synthetic**. No real customer information is used.

## Schema

| Column | Type | Allowed values | Used for |
|---|---|---|---|
| `Customer_ID` | string | unique | tracking selections |
| `Actual_Churn` | int | 0 or 1 | retrospective evaluation only. Never used to choose customers. |
| `Predicted_Churn_Probability` | float | 0–1 | risk signal (stands in for a churn-model score) |
| `Estimated_CLV` | number (€) | > 0 | value potentially preserved |
| `Retention_Offer_Cost` | int (€) | > 0, whole euros | budget consumed by an offer |

Whole-euro costs are required because the dynamic-programming solver indexes the budget in €1 steps.

## Files

### `raw/project_odin_customers.csv`: reference dataset (30 rows)

Hand-built fictional customers used throughout the notebook and as the regression baseline in the tests.

| Statistic | Churn probability | CLV (€) | Offer cost (€) |

| mean | 0.55 | 996 | 100 |
| min | 0.14 | 229 | 40 |

There are 15 actual churners and 15 non-churners. The correlation between the risk score and actual churn is 0.79.

### `synthetic/customer_base_5000.csv`: full subscriber base (5,000 rows × 14 columns)

This is the subscriber base of the fictional client, Aurvandil Media. It was generated by `odin.synthetic.generate_customer_base(n=5000, seed=7)`:

```bash
python -m odin generate --n 5000 --seed 7 --out data/synthetic/customer_base_5000.csv
```

| Column | Type | Description |
|---|---|---|
| `Customer_ID` | string | `AUR-0001` … `AUR-5000` |
| `Actual_Churn` | 0 / 1 | Observed churn in the evaluation window |
| `Predicted_Churn_Probability` | 0–1 | Churn-model score |
| `Estimated_CLV` | € | Expected remaining margin |
| `Retention_Offer_Cost` | whole € | Plan-specific incentive |
| `Plan` | category | Basic €7.99 · Standard €12.99 · Premium €17.99 · Family €22.99 |
| `Monthly_Fee` | € | Monthly price of the plan |
| `Contract` | category | Monthly (≈68%) · Annual |
| `Region` | category | DACH · UK & Ireland · Nordics · Benelux · Southern Europe |
| `Acquisition_Channel` | category | Organic · Paid Search · Partner Bundle · Referral |
| `Tenure_Months` | int | Months since sign-up, Gamma(2, 9), capped at 1–96 |
| `Viewing_Hours_30d` | float | LogNormal with a median of 24 h |
| `Support_Tickets_90d` | int | Poisson(0.6) |
| `Payment_Failures_90d` | int | Poisson(0.22) |

**How churn is generated.** A *true* churn log-odds is built from the drivers:

- **Raise churn:** monthly contract (+0.95), each support ticket (+0.38), each payment failure (+0.85), paid search (+0.30), partner bundle (+0.20) and Basic plan (+0.20).
- **Lower churn:** tenure (−0.028 per month, capped at 48), viewing hours (−0.55 × log ratio), referral (−0.35) and Family plan (−0.30).
- **Noise:** N(0, 0.25) is added to the log-odds.

`Actual_Churn` is drawn from this true probability, giving a base churn rate of about 30%.

**How the score is generated.** `Predicted_Churn_Probability` applies the same log-odds, shrunk by 0.9 and shifted by +0.08, then adds N(0, 0.35) model error. The score is therefore informative (ROC AUC ≈ 0.70) and slightly over-predicts, like a real model.

**How the economics are generated.**

- `Estimated_CLV` = fee × 60% gross margin × expected remaining lifetime, where the lifetime is 18 months + 0.35 × tenure, +12 for an annual contract and +8 for the Family plan, clipped to 12–72 months.
- `Retention_Offer_Cost` = 2 free months (Basic, Standard) or 2.5 free months (Premium, Family) + €3 handling, rounded to whole euros.
